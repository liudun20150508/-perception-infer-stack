# 评测口径与实测结果

## 1. 指标定义

| 指标 | 定义 | 为什么用它 |
|---|---|---|
| `p50_ms` | 端到端单图延迟中位数 | 稳态延迟，代表"通常多快" |
| `p99_ms` | 尾部延迟 | 自动驾驶对长尾敏感，p99 比均值更能反映卡顿 |
| `FPS` | 平均帧率（1000/mean） | 吞吐上限 |
| `mAP50` | IoU=0.5 的平均精度（101 点插值） | 检测质量主指标 |
| `mAP50-95` | IoU 0.5:0.95（步长 0.05）平均 | 定位精度，防止"框对了但框不准" |
| 峰值显存 | `torch.cuda.max_memory_allocated` | 决定能否上小卡/多路 |

**延迟与精度必须同表出现**：只报加速比会把"模型被量化打崩"当成优化成果。

## 4. 实测结果

### 4.1 推理引擎三后端对照（同一套前/后处理）

| 后端 | p50 ms | p99 ms | FPS | mAP50 | mAP50-95 |
|---|---|---|---|---|---|
| torch-FP32（baseline） | 15.09 | 20.33 | 64.4 | 0.6257 | 0.4998 |
| engine-FP32（ONNX+ORT CUDA） | 13.60 | 18.92 | 72.6 | 0.6257 | 0.4998 |
| **engine-INT8（Conv-only 量化）** | **9.62** | 18.69 | **96.5** | 0.6038 | 0.4656 |

结论：INT8 相对 FP32 **加速 1.41x、mAP50 掉 2.2 个点**；是"可接受的降资源"而不是"免费的提速"。

### 4.2 感知前后处理算子（CUDA）

| 算子 | 规模 | GPU | CPU 参考 | 校验 |
|---|---|---|---|---|
| letterbox+bilinear+normalize | 1920×1080 RGB → 3×640×640 | 0.010 ms | 12.0 ms | `max\|diff\| = 5.96e-8` |
| NMS | 3000 框 | 0.438 ms | 31.0 ms | 逐框一致（keep=847） |

### 4.3 量化推理算子

| 算子 | 结果 |
|---|---|
| INT8 GEMM（2048³） | naive 4.72ms / dp4a 5.26ms（0.90x，负结果）/ cuBLAS-INT8 0.165ms（28.7x） |
| FP4(e2m1fn) 反量化 | 1048576 个值 **GPU == CPU 全一致** |

## 5. 口径注意事项

1. **计时取 min-of-N**。共享主机（load 常年在 30~70）上单次测量不可信；本仓库的计时一律多轮取最小值。
2. **区分"确定性证据"与"计时证据"**。CPU 亲和性、NUMA 页分布这类结论，用内核状态
   （`Cpus_allowed_list`、`/proc/self/numa_maps`）判定，而不是用被邻居干扰的耗时。
3. **负结果照报**。例如手写 dp4a 输给 naive（0.90x）——因为没做 shared memory tiling，
   瓶颈在访存不在 ALU。这类结果比"全部更快"更能说明判断依据。
