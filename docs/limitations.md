# 已知限制与负结果

**能力边界写清楚，比含糊地说"都支持"有用。**

## 1. 能力缺口

| 项 | 现状 | 影响 |
|---|---|---|
| TensorRT / 自研 engine | 未接入，只有 ONNX Runtime | 拿不到 TRT 的量级提升；engine 段只到 ORT 层 |
| 真实车端数据 | 用公开 COCO128 小样本 | mAP 不代表业务数据表现 |
| 多卡 / 分布式推理 | 未做 | 只有单卡与多路视频调度 |
| 数据集级回归 | 只有单模型 mAP + 门禁 | 没有跨数据集/跨版本的回归库 |
| 感知任务覆盖 | 只有检测（YOLOv8n） | 分割/跟踪/多模态未涉及 |

## 2. 未修通的负结果（如实登记）

| 项 | 现象 | 已定位到的原因 | 状态 |
|---|---|---|---|
| SGEMM 的 float4 向量化版 | sm_89 上报 `misaligned address` | 对齐假设在 sm_89 不成立 | 未修，分块版可用 |
| FlashAttention 手写版 | 与 naive 对拍 `err/tol=12.47`，且比 naive 慢 0.68x | 在线 softmax 实现有误 | 未修 |
| 手写 dp4a INT8 GEMM | 3926 GFLOPS，是 naive 的 0.90x | 未做 shared memory tiling，瓶颈在访存 | 结论：访存受限，不是 ALU |
| 整图 INT8 量化 | mAP 归零 | 分类分支被量化打崩（max score → 0） | 已规避：只量化 Conv |
| 朴素 FP16 全模型 | 检测框归零 | RPN/ROI 头对数值敏感 | 已规避：用 autocast 混合精度 |

## 3. 环境相关的限制

- 本仓库在**共享主机**上验证，因此涉及的绝对耗时只在同一次运行内可横向比较；
  跨环境只保证**趋势**与**比值**。
- `src/graphics` 是 **CPU 软件光栅化**，用来证明图形管线理解，**不等于 GPU 图形/CUDA 证据**。
- `src/os` 的线程扩展性在共享主机上会呈现"加线程反而更慢"，那是资源竞争而非代码缺陷 ——
  脚本里已注明，并在生产建议里给出 cpuset/绑核方案。

## 4. 数据与许可

- `data/samples/` 为 COCO128 中的 4 张图（公开数据集，遵循其原始许可）。
- 模型权重由 `scripts/fetch_data.sh` 从公开源下载，不随仓库分发。
